# SETUP — bootstrap on a new machine

For a coding agent (or human) setting this repo up fresh. After setup, read
`AGENTS.md` then `STATUS.md` to resume work.

## 1. Prerequisites

- **Node 20.x** (developed on v20.20.0) + npm 10.x
- git
- Optional: Supabase CLI (`npm i -g supabase`), Vercel CLI (`npm i -g vercel`)

## 2. Install

```bash
git clone https://github.com/junho0707/provablelearning.git
cd provablelearning
npm install
```

## 3. Environment variables

Secrets are **not** in git (`.gitignore` blocks all `.env*`). The single source of
truth is `.env.local` on the previous machine — copy it over, or recreate it from
`.env.local.example`.

```bash
cp .env.local.example .env.local   # then fill in real values
```

**Required for M1 (content + practice — the only code that runs today):**

| Var | Where from |
|-----|-----------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project → Settings → API |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | same |
| `SUPABASE_SERVICE_ROLE_KEY` | same (server-only; reads the practice `answer` column) |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` for local |

Content pages render **without** any env (they build from in-repo MDX). Supabase
vars are only needed for practice questions; when absent, `getLessonQuestions`
returns `[]` and pages degrade gracefully.

**Later milestones (present in `.env.local` but unused in M1):** Stripe
(`STRIPE_*`), Google OAuth/Calendar (`GOOGLE_*`), Twilio, Resend, `CRON_SECRET`.
Copy them if you have them; not required to run M1.

**Do NOT hand-copy `VERCEL_OIDC_TOKEN`** — it is auto-generated by `vercel link` /
`vercel dev` and expires.

## 4. Database (only needed for practice questions)

The linked Supabase project ref is `vufizavpkjpybsknvyno` (prod). Migrations
`0001_init.sql` + `0002_questions.sql` and `seed.sql` were verified against a
**local** stack only — see open follow-up in `STATUS.md`.

- Local stack: `supabase start` then `supabase db reset` (applies migrations + seed).
- Remote: **verify the target ref first**, then `supabase db push` and run `seed.sql`
  via the dashboard SQL editor. `0002` uses column-level grants to hide the answer
  column from anon — do not weaken them.

## 5. Verify the setup

```bash
npm test        # 20 passing: content x10, practice/check x7, practice/integrity x3
npm run build   # Next 16, TS strict, no error-ignoring — should be clean
npm run dev     # http://localhost:3000
```

Sanity checks: `/courses` lists the catalog; a lesson page renders MDX + KaTeX;
practice questions appear only if the DB has the `questions` table seeded, and the
served HTML never contains the answer/explanation.
