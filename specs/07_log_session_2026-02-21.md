# Session Progress — 2026-02-21

## What Was Done

### Bugs Fixed

1. **Zod `.partial()` on refined schemas** (`src/lib/validators/module.ts`, `src/lib/validators/cohort.ts`)
   - `.partial()` cannot be used on schemas with `.refine()`.
   - Fix: Extracted base object schema (`moduleFields`, `cohortFields`) separate from the `.refine()` call. `.partial()` is called on the base schema, `.refine()` only on the create schema.

2. **OAuth callback cookies not persisting** (`src/app/(auth)/callback/route.ts`)
   - `exchangeCodeForSession` set cookies via `cookieStore.set()`, but `NextResponse.redirect()` didn't carry them.
   - Fix: Rewrote callback to collect cookies from the Supabase client and set them directly on the `NextResponse.redirect()` response object.

3. **Google OAuth "Unable to exchange external code"**
   - Supabase's OAuth callback URL (`https://<ref>.supabase.co/auth/v1/callback`) was already in Google Cloud Console, but Google OAuth consent screen was in "Testing" mode or client secret mismatch.
   - Fix: User verified credentials matched.

4. **Google OAuth "Database error saving new user"**
   - Auth trigger `handle_new_auth_user` created a students row with `parent_id = NULL`, which fired `trg_enforce_student_phone` requiring a phone number. OAuth users don't have phone yet.
   - Fix: Modified `enforce_student_phone()` trigger to skip enforcement on INSERT (phone collected during onboarding).

5. **Post-login redirect to landing page instead of dashboard**
   - Login page redirected to `window.location.href = '/'`, and middleware didn't redirect authenticated users from `/`.
   - Fix 1: Added `pathname === '/'` to middleware redirect condition.
   - Fix 2: Login page now fetches user role after sign-in and redirects to `/${profile.role}` directly.

6. **Hydration error on login page**
   - `useSearchParams()` without Suspense boundary in Next.js 15.
   - Fix: Split into `LoginForm` (inner) + `LoginPage` (outer with `<Suspense>`).

7. **Google OAuth always assigns 'student' role** (MAJOR)
   - Auth trigger `handle_new_auth_user` defaulted to `'student'` when no role in `raw_user_meta_data`. Google OAuth never sends role metadata.
   - Fix: Rewrote auth trigger to **skip** `public.users` creation when `raw_user_meta_data->>'role'` is NULL. OAuth users get profile created during onboarding instead, where they choose parent/student.

### SQL Changes Applied to Supabase (not in migration files)

These were run directly in Supabase SQL Editor and are NOT in the migration files. If you reset the DB, you'll need to re-apply them.

**1. Updated `handle_new_auth_user` trigger — skip profile creation for OAuth users:**
```sql
CREATE OR REPLACE FUNCTION handle_new_auth_user()
RETURNS TRIGGER AS $$
DECLARE
  v_role user_role;
  v_full_name TEXT;
  v_phone TEXT;
BEGIN
  -- OAuth users won't have role in metadata — skip, let onboarding handle it
  IF NEW.raw_user_meta_data->>'role' IS NULL THEN
    RETURN NEW;
  END IF;

  v_role := (NEW.raw_user_meta_data->>'role')::user_role;
  v_full_name := COALESCE(
    NEW.raw_user_meta_data->>'full_name',
    NEW.raw_user_meta_data->>'name',
    ''
  );
  v_phone := NEW.raw_user_meta_data->>'phone';

  IF v_role = 'admin' THEN
    RAISE EXCEPTION 'Admin accounts cannot be self-created';
  END IF;

  INSERT INTO public.users (id, role, full_name, phone)
  VALUES (NEW.id, v_role, v_full_name, v_phone)
  ON CONFLICT (id) DO NOTHING;

  IF v_role = 'student' THEN
    INSERT INTO public.students (user_id, parent_id, active_status)
    VALUES (NEW.id, NULL, 'active')
    ON CONFLICT (user_id) DO NOTHING;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER SET search_path = public;
```

**2. Updated `enforce_student_phone` trigger — skip on INSERT:**
```sql
CREATE OR REPLACE FUNCTION enforce_student_phone()
RETURNS TRIGGER AS $$
DECLARE
  v_phone TEXT;
BEGIN
  IF TG_OP = 'INSERT' THEN
    RETURN NEW;
  END IF;

  IF NEW.parent_id IS NULL THEN
    SELECT phone INTO v_phone
    FROM public.users
    WHERE id = NEW.user_id;

    IF v_phone IS NULL OR v_phone = '' THEN
      RAISE EXCEPTION 'Phone number is required for independent students';
    END IF;
  END IF;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**3. Added RLS policies for onboarding self-insert:**
```sql
CREATE POLICY users_insert_own ON public.users
  FOR INSERT
  WITH CHECK (id = auth.uid());

CREATE POLICY students_insert_own ON public.students
  FOR INSERT
  WITH CHECK (user_id = auth.uid());
```

**4. Created `admin_set_role_parent` RPC (may not be needed now, but exists):**
```sql
CREATE OR REPLACE FUNCTION admin_set_role_parent(target_user_id UUID)
RETURNS void AS $$
BEGIN
  ALTER TABLE public.users DISABLE TRIGGER trg_prevent_role_change;
  UPDATE public.users SET role = 'parent' WHERE id = target_user_id;
  DELETE FROM public.students WHERE user_id = target_user_id;
  ALTER TABLE public.users ENABLE TRIGGER trg_prevent_role_change;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```
