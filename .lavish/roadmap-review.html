The format you'll write in

Each lesson is one MDX file (explanation + worked examples, together) plus question rows in Supabase, joined by the lesson slug. This is the whole contract — nothing else to learn. Your coding agent can generate straight into these shapes.

MDX

Explanation

content/…/<slug>.mdx
---
title: Segments, Midpoints & Distance
slug:  segments-midpoints-distance   # must == filename
order: 2                            # position in the theme
summary: One line — used on cards + SEO.
---

Prose in plain Markdown. Inline math with
$AB + BC = AC$, and display math:

$$
d = \sqrt{(x_2-x_1)^2 + (y_2-y_1)^2}
$$

## A section heading
Bold **key terms**, bullet lists, etc.
Only 4 frontmatter fields. Math is KaTeX ($…$ / $$…$$), rendered server-side. Standard Markdown only — no imports or components to learn.
MDX

Worked examples

same file
# Examples live in the SAME lesson file —
# a heading convention, not a new format.

## Example 1 — Distance on a number line

Find $AC$ if $AB = 5$ and $BC = 3$,
with $B$ between $A$ and $C$.

Since the point is between, lengths add:
$$ AC = AB + BC = 5 + 3 = 8 $$

> **Takeaway.** Betweenness lets you add
> segment lengths directly.
Proposed convention: an ## Example heading + a > takeaway blockquote. Consistent & searchable. Want richer styled example boxes (a colored callout component)? That's a ~small renderer add — flag it in the decisions below.

Practice questions

Supabase · questions table, keyed by lesson slug
-- 3 question types. answer/tolerance/explanation are HIDDEN from the browser (server-checked).
insert into questions (lesson_slug, position, type, prompt, choices, answer, tolerance, explanation) values

-- MULTIPLE CHOICE — choices as JSON, answer = the correct id
('segments-midpoints-distance', 1, 'mcq',
 'If B is the midpoint of AC and AC = 12, what is AB?',
 '[{"id":"a","label":"3"},{"id":"b","label":"6"},{"id":"c","label":"12"},{"id":"d","label":"24"}]',
 'b', null, 'A midpoint splits the segment in half: 12 / 2 = 6.'),

-- NUMERIC — answer is a number, tolerance = accepted +/- slack (0 = exact)
('segments-midpoints-distance', 2, 'numeric',
 'Find the distance between (0,0) and (3,4).',
 null, '5', 0, '√(3² + 4²) = √25 = 5.'),

-- FREE RESPONSE — no auto-grade; reveals the explanation on submit

Batch-friendly: write these in dev, verify, then push to the prod DB. One caveat for repeatable batches (from the deploy plan): plain inserts duplicate if re-run — I'll set up an idempotent convention so each batch is safe to push. The lesson_slug must match a real MDX file (a test enforces it).
