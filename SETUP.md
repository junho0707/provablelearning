# SETUP — bootstrap on a new machine

For a coding agent (or human) setting this repo up fresh. After setup, read
`AGENTS.md` then `STATUS.md` to resume work.

## 1. Prerequisites

- **Node 20.x** (developed on v20.20.0) + npm 10.x
- git
- Optional: Supabase CLI (`npm i -g supabase`), Vercel CLI (`npm i -g vercel`)

## 2. Install

```bash
git clone https://github.com/junho0707/provablelearning.git
cd provablelearning
npm install
```

## 3. Environment variables

Secrets are **not** in git (`.gitignore` blocks all `.env*`). The single source of
truth is `.env.local` on the previous machine — copy it over, or recreate it from
`.env.local.example`.

```bash
cp .env.local.example .env.local   # then fill in real values
```

Content pages render **without** any env (they build from in-repo MDX). Everything
else needs Supabase; M4+ also needs Stripe/Google/Resend/`CRON_SECRET` — see
`VERIFY.md` for exactly which section needs which vars.

| Var | Where from |
|-----|-----------|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` | Supabase project → Settings → API |
| `NEXT_PUBLIC_APP_URL` | `http://localhost:3000` for local |
| `STRIPE_*`, `GOOGLE_*`, `RESEND_*`, `CRON_SECRET` | see `.env.local.example` comments; each is only needed once you reach that section of `VERIFY.md` |

**Do NOT hand-copy `VERCEL_OIDC_TOKEN`** — it is auto-generated by `vercel link` /
`vercel dev` and expires.

## 4. Database

All 14 migrations in `supabase/migrations/` (0001 through 0014) plus `seed.sql`
need to be applied, in order. **None have been applied anywhere except locally
during development** — this has never been exercised against a real project.

- Local stack (needs Docker): `supabase start` then `supabase db reset` (applies
  every migration + seed in one shot).
- Remote: `supabase link --project-ref <ref>` (**verify the ref first** — the
  linked CLI has previously pointed at the prod ref `vufizavpkjpybsknvyno` by
  default), then `supabase db push`, then run `seed.sql` via the dashboard SQL
  editor.

Migrations `0002`/`0012` use column-level grants to hide answer columns from
`anon` — do not weaken them.

## 5. Verify the setup

```bash
npm test        # 181 passing — no live services needed
npm run build   # Next 16, TS strict, no error-ignoring — should be clean
npm run dev     # http://localhost:3000
```

That confirms the code builds and its own logic is correct. It does **not**
confirm anything that touches a live database, Stripe, Google, or Resend — none
of that has been exercised. For that, work through **`VERIFY.md`** top to bottom
(§0 environment setup, then §1–§5 in order). It has one entry per RPC/webhook/
integration with the exact manual steps and expected result.

**Admin bootstrap** (no UI for this): after signing in once via `/login`, in the
Supabase SQL editor run:
```sql
update accounts set is_admin = true where email = 'you@example.com';
```

Read `AGENTS.md` (operating rules) → `STATUS.md` (current position) → `VERIFY.md`
(what to verify). As of 2026-08-14, **every task in `spec/12_IMPLEMENTATION_PLAN.md`
with a code deliverable is code-complete through M7** — there is no next
